How it works

No changes to your server. Attestry speaks MCP and the standard OAuth flows MCP clients already use.

  1. Connect your server

    Paste your MCP server URL and get a gateway URL such as acme-crm.gw.attestry.dev/mcp. A security scan flags risky tools and applies safe defaults.

  2. Agents sign in properly

    Clients discover your authorization server, register, ask the user for consent and receive tokens valid for your server only. API keys are there for server-to-server use.

  3. Every call is limited, measured and signed

    Plans and per-tool scopes are enforced with clear messages agents understand. You see who calls which tools, and every call gets a signed receipt anyone can verify.

What you get

Everything you'd otherwise build yourself before opening an MCP server to the world.

OAuth for MCP, done right

Standards-based sign-in for agents and MCP clients: discovery metadata, client registration, PKCE, consent screens and tokens bound to your server.

Keys, plans and a consumer portal

Consumers create keys themselves on the plans you define, with per-tool scopes and quotas.

Limits agents understand

Per-consumer, per-tool and per-plan limits that return clear "retry after" messages instead of silent failures.

Know who's calling

See which agents, clients and consumers use which tools, with errors, latency and trends, and spot who's ready to upgrade.

Abuse protection

Catch scraping, shared credentials and unusual bursts; recognise verified agents and treat unknown ones with care.

Proof for every call

Every call, allowed or refused, gets a signed, chained receipt you, your customers or an auditor can verify.
